# Superseded product plan

The September 1 exploration in this file described a larger product with accounts, projects, permanent inboxes, Postgres, backups, scheduled jobs, and an embeddable website widget. Those ideas are no longer the Raise roadmap.

Use these records instead:

- [Product requirements](PRD.md) owns the approved product behavior and exclusions.
- [Architecture](architecture.md) owns the accepted Redis/Valkey, encrypted blob, and single-instance design.
- [Delivery plan](PLAN.md) owns implementation order, status, acceptance checks, and remaining work.
- [Architecture decisions](architecture/decisions/README.md) records choices that would be expensive to reverse.

Git history preserves the earlier exploration if its research is ever needed. Don't copy requirements from an older revision into current work without owner review.
